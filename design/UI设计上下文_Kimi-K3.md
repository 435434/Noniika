## 1. 项目背景与设计目标

### 1.1 产品是什么

- **Noniika**（面板标题用花体 **𝙉𝙤𝙣𝙞𝙞𝙠𝙖**，署名作者 **𝙁𝙖𝙙𝙚**）· v0.9.0 · 基础版
- 一个 After Effects **CEP 扩展面板**：在 AE 时间线上选中素材图层 → 一键完成
  「按选中区间导出音频 →（可选）本地分离人声 → 云端 ASR 识别 → 在同一合成内创建字幕文本图层」
- 三层架构：CEP 面板（HTML/JS）⇄ ExtendScript 桥接（`ae-bridge.jsxbin`）⇄ 外部 Node 流水线（`pipeline/cli.js`，零 npm 运行时依赖，自带 LGPL ffmpeg 与 node.exe）
- 扩展 ID `com.aesub.autosubtitle`（**不可改**——改了等于另一个扩展，老用户升级会新旧并存）

### 1.2 本次设计要解决的问题（真实痛点，均有据可查）

| # | 痛点 | 来源 |
|---|---|---|
| P1 | 用户不知道"当前实际用哪个模型/引擎"，要翻运行日志 | 用户原话反馈，已部分修复（日志已报模型），但首页仍不可见 |
| P2 | 没配密钥时，点了「生成字幕」才报错 | 密钥是 v0.9.0 新增的硬前置条件 |
| P3 | 跑任务时只有一个百分比+一行字，不知道四步（导出/分离/识别/建层）走到哪 | 流水线其实按 step 上报，界面没利用 |
| P4 | 字幕样式改完看不到效果，要生成一次才知道 | 样式页无预览 |
| P5 | 环境/依赖状态是纯文字行，扫一眼难判断哪些就绪 | 人声分离页、设置页 |
| P6 | 长密钥粘贴容易错，无法核对 | 密钥输入框无显示切换 |

### 1.3 设计目标与红线

**目标**
1. 保持 AE 原生深色质感——**不换风格，只调层次**；信息密度不能降（这是工具面板，不是营销页）
2. 主操作路径三击可达：选素材 → 点「生成字幕」→ 看（新建字幕图层）
3. **按键布局符合直觉**（本次新增的硬要求，见 §3.6）
4. 状态可见：引擎/模型/密钥/环境/进度，一眼可判

**红线（不可违反）**
- 不删任何现有功能与配置项（4 页 + 3 弹窗全部保留）
- 不改扩展 ID、不改数据目录名 `我的文档\AE自动字幕`（那里放着 7 GB 分离环境，改名会让用户重下）
- 花体字符 𝙉𝙤𝙣𝙞𝙞𝙠𝙖 / 𝙁𝙖𝙙𝙚 只用于 HTML 界面与文档；**绝不能出现在 .bat、压缩包文件名、任何要进 cmd 的地方**（实测：全机 362 个字体中只有 Segoe UI Symbol / Cambria Math 能渲染，cmd 控制台字体没有该字形）
- 深色体系已通过 `color-scheme: dark` + 滚动条/密码框定制解决"白块"问题，不能回退

## 2. 目标用户画像与典型使用场景

### 2.1 用户画像

- 视频后期/混剪作者（抖音账号运营），AE 熟练用户；**简体中文**，Windows 11，150% 显示缩放
- 机器：RTX 4060 Laptop 8GB / 16GB 内存 / C 盘空间紧张（工具需明确告知体积代价）
- 有免费优先倾向：默认走免费识别档，不轻易付费；对"上传了什么、传给谁"敏感
- 常处理带 BGM 的素材 ⇒ 人声分离是核心差异化卖点

### 2.2 典型场景（按频率排序）

| 场景 | 用户动作 | 界面要求 |
|---|---|---|
| S1 混剪出字幕（最高频） | 选素材 → 生成字幕 → 微调样式 | 首页一切就绪态一目了然；引擎状态条可见 |
| S2 只要人声 | 选素材 → 分离人声 | 与 S1 同级入口，明确"不上传云端" |
| S3 首次配置 | 装插件 → 填密钥 → 测试 | 引擎档位说明清晰；「测试密钥」零额度可验证；失败原因可读 |
| S4 排障："字幕建了但看不见" | 字幕样式页 → 体检 | 只读检查，按钮语义不能像"会改东西" |
| S5 磁盘/内存维护 | 清理内存 / 插件文件 / 模型 | 破坏性操作必须确认弹窗+清单，回收站语义 |
| S6 等长任务 | 分离 10~30 分钟 / 识别上传 | 进度必须分步可见，等待期可读日志 |

## 3. 设计规范

### 3.1 色彩体系

**现状 token（`cep/css/style.css` `:root`，实测）**

| Token | 值 | 用途 |
|---|---|---|
| `--bg` | `#232323` | 窗体背景 |
| `--panel` | `#2b2b2b` | 卡片/开关容器 |
| `--panel2` | `#343434` | 输入框/次级按钮 |
| `--line` | `#3d3d3d` | 描边 |
| `--fg` | `#d8d8d8` | 主文字（对 bg 对比度 ≈ 9.9:1 ✓） |
| `--fg-dim` | `#9c9c9c` | 次级文字 |
| `--fg-hint` | `#7e7e7e` | 提示文字（对 panel ≈ 4.0:1，临界——只能用于非关键信息） |
| `--accent` | `#4a9eff` | 主色/进度条/焦点 |
| `--ok` `--warn` `--err` | `#7ddba3` `#f0c869` `#f09a9a` | 语义色 |
| `--radius` | `6px` | 现行圆角（**提案改 8px**） |

**硬编码色（同样在用）**：卡片描边 `#383838`；主按钮底 `#2f5f9e` / 描边 `#3b76c2` / 字 `#eaf2ff`；日志底 `#1c1c1c`；徽章底 `#3a3a3a` 字 `#a8a8a8`；tip 警示底 `#3a3117` 描边 `#5a4416` 字 `--warn`。
**提案补充**：主按钮渐变 `linear-gradient(180deg,#3a74c4,#2e5c9a)`、焦点描边 `#4a86d8`、步骤条激活底 `#26374e`、完成态底 `#243428`。

**规则**：语义色永远"圆点 + 文字"成对出现（不允许只用颜色区分状态）；新增色一律走 token，不再加硬编码。

### 3.2 字体排印

| 层级 | 规格 | 用途 |
|---|---|---|
| 基准 | `12px / 1.6 "Segoe UI","Microsoft YaHei",system-ui` | 全局 body |
| 面板标题 | h1（花体 𝙉𝙤𝙣𝙞𝙞𝙠𝙖），提案 16px / 加字距 | 页眉 |
| 卡片标题 | `11px #8f8f8f`，字距 .3px | card-title / summary |
| 提示文字 | `11px / 1.5~1.65` | hint / footnote / stateRow |
| 等宽 | `11px/1.55 Consolas,"Courier New"` | 运行日志、路径类信息（.mono） |
| 徽章 | `11px`，圆角 9px 胶囊 | envBadge 等 |
| 按钮主文案 | b `13px`（提案 13.5px）+ 副题 span `10px` | runbtn/navbtn 两行式 |

花体字符渲染依赖系统回退（Segoe UI Symbol / Cambria Math）；标准 Windows 可显示，需在低配置机器上容忍方框风险（已实测留档 `design/署名花体_字体渲染验证.png`、`design/标题花体_渲染验证.png`）。

### 3.3 间距与栅格

- `.app` 内边距 10px（提案 12px）；卡片纵向间距 10px（提案 margin-top:10px 统一）
- 卡片内边距 `8px 10px`；行（.row）为 `label + control` 横排，gap 6px
- 按钮组 `.actions`：两列 `.split`（等分）、整行 `.fill`、次级 `.sub`；组内 gap 6px
- **栅格基准 4px**：所有 gap/padding 取 4 的倍数（4/6/8/10/12）
- 单列自适应流式布局（无多栏），宽度由面板决定

### 3.4 圆角 / 描边 / 投影

- 圆角：卡片/主按钮 提案统一 8px；次级按钮/输入框 7px（提案）/4px（现状）；胶囊 9~11px
- 描边一律 1px 实线；卡片提案加 `inset 0 1px 0 rgba(255,255,255,.03)` 顶部高光
- 无大面积投影（面板内）；外壳演示帧的投影不进面板

### 3.5 图标与插画风格

- **无插画**。图标仅两处来源：① 内联 SVG 16px 单色描边（如清理按钮的垃圾桶/水滴，stroke 风格，`currentColor`）② Unicode 字符（⚙ 设置、← 返回、☆/★ 收藏、▶ 播放）
- 规则：新图标继续用内联 SVG 描边风格，尺寸 16px，不加彩色/填充风图标
- 字幕预览框是**功能组件**（见 §4.3），不是插画

### 3.6 按钮体系与"直觉性布局"原则（本次硬要求）

**按钮四级层级**

| 层级 | 类名 | 样式 | 用途 |
|---|---|---|---|
| 主操作 | `.primary`（常与 `.runbtn` 连用） | 蓝底渐变、每屏唯一 | 生成字幕 / 弹窗推荐动作 / 确认清理 |
| 次操作 | 默认 `button` / `.small` | panel2 底 | 下载模型、试导出等并列动作 |
| 弱操作 | `.ghost.small` | 同上但文字弱化 | 刷新/测试密钥/清理类/取消 |
| 导航卡 | `.navbtn` | 两行式卡片按钮 | 去人声分离设置 / 去字幕样式 |

**直觉性布局七原则**（评审 UI 时逐条对照）
1. **操作顺序 = 阅读顺序**：素材信息 → 主动作 → 子设置入口 → 开关 → 进度 → 结果 → 日志（现状首页已符合，勿打乱）
2. **每屏一个 primary**；与主操作并排的只能是同级备选（分离人声 vs 生成字幕），备选用默认层级
3. **破坏性动作降级+隔离**：清理类永远 ghost 小按钮、放独立 `.maint` 区、点了走确认弹窗；弹窗里"覆盖旧产物"用 ghost，推荐项（跳过分离）才是 primary
4. **弹窗按钮顺序**：推荐动作（primary）→ 替代动作（ghost）→ 取消（ghost，最右）；`Esc`/点遮罩 = 取消
5. **两行式按钮**：主文案讲"是什么"，10px 副题讲"具体做什么"（如「分离人声 / 只分离，不识别字幕」）——不允许出现无副题的含糊动词
6. **导航入口带状态摘要**：按钮副题显示当前值（「当前：开 · Kim Vocal 2」「每句一层 · 72 · 华文行楷」）
7. **位置守恒**：⚙ 永远右上（去设置）、← 永远左上（返回首页）、总开关常显不折叠

## 5. 交互模式与状态设计

### 5.1 控件状态矩阵

| 状态 | 规范 |
|---|---|
| 默认 | 见 §3 token；按钮 cursor:pointer |
| 悬停 | 描边提亮（现有 button hover 提亮描边/文字）；chips 描边→`#5a7ba6` |
| 焦点（键盘） | 提案 `:focus-visible` 2px `#4a86d8` 外描边 + 1px offset（现状缺失，必须补） |
| 禁用 | 降透明 + cursor:default；**禁用必须给原因**（相邻 hint 说明，如"没有可复用的人声文件"） |
| 加载 | 文案占位：徽章「检测中…」、select「（读取中…）」、hint「正在读取…」；不可用"转圈图" |
| 忙碌 | 任务运行中：主按钮禁用、进度条+status 行、（提案）步骤条点亮；清理类互斥（busyClean） |
| 错误 | 日志行红色(.err)、结果卡 `.tip.bad` 红框、徽章变语义色；错误文案必须含"下一步怎么做" |
| 空态 | 素材未选：selHint 给引导（"在时间线上选中要处理的图层"）；列表空给"点这里重新扫描" |
| 成功 | 日志行绿色(.ok) + "√"前缀；徽章「环境就绪」 |

### 5.2 运行进度映射（来自流水线真实上报）

导出 0-8 → 转码 8 →（分离，本地长任务）→ 识别上传 15-85 → 后处理 90 → 建层/收尾 100。
步骤条与 status 行必须同源：`{step, message, percent}` JSON 行事件。

### 5.3 异步约定

- 所有 AE 桥接/子进程调用走 Promise 链；等待期写入 status，不阻塞 UI
- 「测试密钥」：零额度验证 + 顺带拉取服务商 `/v1/models` 实时清单灌入「挑一个」；结果写日志（含"档位默认"标注）
- 取消语义：用户主动取消（userCancel）不算错误，日志中性提示、不弹红色

## 6. 可访问性与响应式

- **面板尺寸**：默认 460×720，最小 360×420（manifest `<Size>/<MinSize>`，**不可改约束**）；任意高度可拉伸，内部滚动（`overflow-x:hidden`）
- 360 宽下必须复核：`.split` 两按钮不折行错位、`.statgrid`/`.envgrid` 2 列是否退化单列、两行式按钮副题不截断
- 对比度：正文/按钮文字 ≥ 7:1；`--fg-hint` 仅用于非关键说明；语义状态必须"圆点+文字"双编码
- 键盘可达：Tab 顺序按视觉流；所有 checkbox 用整行 label 可点（现状已符合）；补 `:focus-visible`
- 触达面积：按钮高度 ≥ 26px（现状 5px+10px padding 满足）；勾选框行高 1.5+
- DPI：用户 150% 缩放——字号用 px 时按 12px 基准已验证可读，勿引入 <10px 文字
- 语言：全部简体中文；技术名词首现给白话副题（两行式按钮就是载体）

## 7. 平台约束（CEP/AE 特有，设计必须绕开）

1. 普通超链接 `<a>` 点击无效 ⇒ 外链必须走按钮 + `cep.util.openURLInDefaultBrowser`
2. `<datalist>` 在 CEF 里"不打字不弹出、无箭头"（已踩坑）⇒ 下拉选择一律用 `<select>` 或 select+input 组合
3. `type="password"` / 原生控件深色靠 `color-scheme:dark` + 显式 CSS ⇒ **新增任何 input 类型都要回补表单选择器**（历史上漏过 password 出现白框）
4. 面板设置存 localStorage（`aesub.*`），改动即时保存——新控件必须接 persistKeys
5. 密钥经环境变量传给子进程（不进命令行/日志/产物）
6. 只改 HTML/CSS/JS 重载面板即生效；改 `.jsx(bin)` 必须重启 AE——设计评审时若涉及桥接数据（如预览框要读真实样式），要标注实现层级
