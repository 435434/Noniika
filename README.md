# Noniika · AE 自动字幕插件

在 After Effects 的**时间线上选中要处理的素材**，一键完成：
**导出这段音频 → （可选）分离人声 → 云端 ASR 转写 → 在同一个合成里创建字幕文本图层**。

识别引擎**可切换、与服务商解耦**：默认用**免费档**（硅基流动 SenseVoice，注册即用、
不收费不限量），也可以在面板里换成回**真时间戳**的档位（腾讯云录音文件识别、
Groq Whisper），或指向你自建的 OpenAI 兼容服务。

**需要你自备一个识别服务商的 API Key**（免费档也要注册领 key，但不用花钱）。

> **只想用插件？** 到 [**Releases**](../../releases) 下载 `Noniika-v0.9.1.zip`，
> 解压后双击 `一键安装.bat`，重启 AE 就能用。源码结构与开发说明在下面。

> 隐私底线：识别时音频会上传到**你所选服务商**的云端。**请勿处理机密内容。**
>
> 本插件是**独立的第三方工具**，与 Adobe Inc. **没有任何关联**，未获其赞助、认可或授权；
> 名称中的"AE"指代 Adobe After Effects，仅用于说明本插件的**兼容对象**。

## 二、工作流（v0.2 起）

```
时间线上选中素材图层
        ↓
面板算出这些图层在时间轴上的区间 [rangeStart, rangeEnd]
        ↓
只导出这一段（不是整段合成！）→ 中间音频文件
        ↓                      文件时间 0 秒 == 合成时间 rangeStart 秒
Node 流水线：转 16kHz 单声道 → 云端 ASR（+ 必要时切块）→ 后处理
        ↓              并整体平移 +rangeStart，让字幕对齐合成时间轴
回到 AE，在同一个合成里创建字幕图层
        ↓
删除中间音频（默认，可关）
```

**为什么必须按范围导出**：合成时长常常远大于有声音的区间。
实测遇到过 10800 秒（3 小时）的合成里只有十几秒人声，
按整段导出会产出 **1.98 GB** 的静音，转码后仍有 329 MB ——
既慢又会硬撞各服务商的单文件上限（免费档常见 25~50 MB，
腾讯云"直接传数据"这条路只有约 5 MB）。按范围导出是最省事、最省额度的一刀。

## 四、安装

### 1. 扩展

把 `cep/` 的内容复制到 CEP 扩展目录，文件夹名必须是 bundle id：

```
C:\Users\<你>\AppData\Roaming\Adobe\CEP\extensions\com.aesub.autosubtitle\
```

未签名扩展需要开启调试模式，否则 AE 不会加载。对 CSXS 9～12 各建一个字符串值：

```
HKEY_CURRENT_USER\Software\Adobe\CSXS.9   PlayerDebugMode = "1"
HKEY_CURRENT_USER\Software\Adobe\CSXS.10  PlayerDebugMode = "1"
HKEY_CURRENT_USER\Software\Adobe\CSXS.11  PlayerDebugMode = "1"
HKEY_CURRENT_USER\Software\Adobe\CSXS.12  PlayerDebugMode = "1"
```

### 2. 流水线依赖（v0.9.0 起**不需要 npm install**）

分发包里已经自带一切，**没有任何运行时 npm 依赖**：

```
pipeline/
├─ cli.js              流水线入口
├─ lib/                识别编排 / 各家适配器 / ffmpeg 封装 / 后处理
└─ vendor/ffmpeg/      随包 ffmpeg（LGPL 构建）+ 许可全文
```

开发机（本仓库）上如果想用系统或 npm 版的 ffmpeg 兜底，才需要：

```bash
cd pipeline
npm install            # 只为拿到 @ffmpeg-installer 里的 ffmpeg 作兜底，可选
```

查找顺序是 `AESUB_FFMPEG 环境变量 → pipeline/vendor/ffmpeg → node_modules → 系统 PATH`，
见 `pipeline/lib/paths.js`。

> **为什么分发包不带 `node_modules`**：识别不再依赖任何第三方库
> （v0.9.0 起走 `lib/providers/` 里的纯 HTTP 适配器，只用 Node 标准库 + 内置 `fetch`）。
> 少带一棵依赖树，就少一份许可义务与一个体积包袱。

### 3. AE 脚本权限

AE 需要允许脚本写文件，否则面板会静默失败：

```
编辑 > 首选项 > 脚本与表达式 > 勾上「允许脚本写入文件和访问网络」
```

## 五、使用

### 面板

1. 双击进入一个合成（时间线）
2. **在时间线上选中要处理的素材图层**（不选也行：会自动取合成里全部带音频的图层）
3. `窗口 > 扩展 > Noniika` → 点「**▶ 生成字幕**」（只要人声就点左边的「分离人声」）

主干只占四块：**选中的素材 / 开始按钮 / 两个菜单入口 / 总开关 + 进度**。设置按功能拆成独立的页面：

| 层级 | 页面 | 怎么进 | 内容 |
|---|---|---|---|
| 一级 | **首页** | — | 选中的素材、**主操作一分为二（分离人声 / 生成字幕）**、**人声分离设置 / 字幕样式** 两个入口（按钮上直接显示当前值）、**清理内存 / 清理插件文件**、**总开关**、进度、结果摘要、运行日志（收起） |
| 二级 | **人声分离** | 首页「人声分离设置」 | 开关、分离目标、模型、输出格式、本地依赖状态灯、一键安装环境 / 下载模型 / **清理模型**、**字幕动画（短句不加预设）** |
| 二级 | **字幕样式** | 首页「字幕样式」 | 排布、**图层命名（文字内容 / 前缀+序号）**、字体（搜索 + 拾取 + 刷新）、**字号 + 颜色同行**、**文字动画预设（可搜索）**、**字幕体检（查"建了层却看不见"）** |
| 二级 | **设置** | 首页右上角 ⚙ | 识别选项、输出与日志、环境与诊断 |

每个子页左上角有 `←` 返回首页，层级恒定两级，不会越点越深。

**「识别完成后在 AE 中创建字幕图层」总开关**：决定整件事到底有没有结果。
关掉它只会产出 `.srt` / `.json` 文件，不会在 AE 里建图层；此时会有橙色提示、
主按钮也会变成「开始生成（只出字幕文件）」。

> 这个开关以前藏在折叠的「字幕样式」里，结果就是"面板说完成了、时间线上却什么都没有"。
> v0.3.3 起挪到主干常显，并加了存档迁移：老存档里若它是关的，会自动恢复为开启并在日志里说明。

**「试导出」与「用已有字幕建图层」**（在 ⚙ 设置 → 输出与日志 里）：

- 「试导出」只做「选中素材 → 导出音频」，不上传云端、不花钱，用来零成本验证导出环节（报告区间、偏移量、体积、耗时）
- 「用已有字幕建图层」直接拿输出目录里同名的 `.json` 建图层，**不重新识别、不上传云端**。
  用于两种情况：上次忘了开总开关、或想换个字体重做一遍

### 人声分离（可选，本地运算）

素材里有背景音乐时，直接送识别会被音乐干扰。开启后流程变成：
**AE 导出音频 → 本地分离人声 → 只把人声送云端识别**。

在首页点「人声分离设置」进入：

| 项 | 说明 |
|---|---|
| 分离目标 | 仅人声（去背景音乐）/ 仅伴奏（做卡拉OK）/ 人声 + 伴奏都保留 |
| 模型 | 按**人声质量**排序的下拉（见下表），默认 Kim Vocal 2 |
| 输出格式 | WAV 无损 / FLAC / MP3 320k |
| GPU 加速 | 开关（默认开）。检测到 NVIDIA 显卡时装 CUDA 版，快很多倍 |
| 本地依赖 | 状态灯：Python / audio-separator / 运算设备 + **两个加速后端分别可见** |

**模型怎么选**（SDR 分数取自 `audio-separator --list_models` 在本机的实测输出，越高越好；
经验值：**+3 dB ≈ 感知质量翻倍**）：

| 模型 | 人声 SDR | 伴奏 SDR | 推理后端 | 适合 |
|---|---|---|---|---|
| MelBand Roformer（`vocals_mel_band_roformer`） | **12.6** ⭐ | — | torch | 只做人声识别、追求最干净 |
| MelBand Big Beta4 / Kim FT / Beta5e | 12.5 / 12.4 / 12.4 | — | torch | 同上，备选 |
| BS-Roformer 1297 | 11.8 | **16.5** ⭐ | torch | 人声与伴奏都要好 |
| BS-Roformer 1296 | 12.1 | 16.3 | torch | 同上，人声略高 |
| Demucs v4 FT | 10.8 | — | torch | 需要四轨（鼓 / 贝斯） |
| **Kim Vocal 2**（默认） | 10.2 | 15.4 | ONNX | 速度优先，任何设备都能跑 |

**GPU 加速**：勾上「GPU 加速」后装 CUDA 版，实测提速见下方。
两个推理后端**相互独立**，面板会分别显示（`torch √` / `ONNX √`）：

- `torch` —— Roformer / Demucs 这类 `.ckpt` 大模型走它
- `ONNX` —— MDX-Net 这类 `.onnx` 模型走它

> ⚠ **Windows 上一个非常隐蔽的坑**：pip 把 CUDA 库装在 `site-packages/nvidia/` 下
> （新版布局还是非标准的 `nvidia/cu13/bin/x86_64/`），而 Windows 的 DLL 搜索路径**不含**那里。
> `onnxruntime-gpu` 找不到 `cublasLt64_13.dll` 时**不报错，直接静默降级到 CPU** ——
> 表面看"GPU 装了却没用"。本项目在 spawn 子进程时自动把这些目录注入 PATH
> （`separate.js` 的 `envWithRuntimeDirs`），所以面板显示 `ONNX √` 是真的在 GPU 上。

**首次使用需要装环境**：点「一键安装环境」会自动检测 NVIDIA 显卡（`nvidia-smi`）并装对应版本：

- **CPU 版**（无 N 卡，约 1.5 GB）：`audio-separator[cpu]`
- **GPU 版**（勾了「GPU 加速」且有 N 卡，约 4 GB）：额外装
  `onnxruntime-gpu[cuda,cudnn]`（CUDA 13 运行库）与 CUDA 版 PyTorch
  （后者从 PyTorch 官方源拉，国内可能偏慢）

环境建在项目下的独立 venv（`python-env/`），删掉该目录即可完全卸载。
优先走清华镜像，失败自动回退官方源。模型在首次用到时自动下载到 `models/uvr/`。

### 字幕建好了但画面是空的？点「字幕体检」

最常见的原因**不是**字幕坏了，而是**被盖住了**：素材是后放进合成的，落在图层栈最上面，
把下方的字幕整片遮住 —— 时间线上图层名、文字内容一切正常，画面就是空的。

「字幕样式 → 字幕体检」会逐一报出五种成因（**只读，不改任何东西**）：

| 报出的问题 | 含义与处理 |
|---|---|
| **有图层开了「独奏」** | 最诡异的一类：开了独奏后**只有这些层会被渲染**，字幕属性再正常也看不见。把那个独奏按钮（实心圆）点掉即可 |
| **被上方图层盖住** | 上方某个带视频的层不透明地压着字幕。把字幕层拖到图层栈最上方即可 |
| 勾了「羞怯」/ 是「导引层」 | 时间线上方的「隐藏羞怯图层」开着时会隐藏；导引层不参与渲染 |
| **填充色带了 0 透明度** | 填充是 rgba 且 alpha=0 → 文字被画成全透明（属性看着全对） |
| **字体在 AE 里解析不到** | 字体被卸载或移走，AE 找不到字形就画不出东西 |
| 文字动画器把不透明度压到 0 | 预设留下的不透明度动画器会让整句不可见 |
| 文字内容是空白 | ASR 幻觉段留下的空层，删掉或重新识别 |
| 图层被关闭 / 不透明度 0 | 打开眼睛图标 / 把不透明度调回 100% |
| 出入点零长 | 时间戳异常，时间轴上一瞬即过，建议重新识别 |

体检还会抽样显示一层的「文字 / 不透明度 / 时间区间 / 是否被遮挡」，方便直接对照。

**渲染验证（最关键的一步）**：体检还会在该层的时间中点**真渲染两帧** —— 一帧该层开着、一帧关掉它 —— 再逐字节比对（面板用 md5）：



| 结果 | 含义 |

|---|---|

| 两帧**不同** | 这层确实往画面上画了内容，字幕本身没问题（画面仍空就是看错合成或时间点，或需要清缓存） |

| 两帧**完全相同** | 这层对画面**零贡献** —— 属性层面一定还有没查出来的原因，日志会把可疑项都列出来 |



> 这一步会**瞬间关一下该层再恢复**（日志里会明说），除此之外不改任何东西。AE 偶尔只写出第一帧，日志会提示「再点一次体检」。

### 动画铺满整句 + 按真实语音校正时间（v0.7.0）

**① 动画铺满整句**：预设动画本身是固定长度的（比如 2 秒），而每句字幕长短差很多。
现在会量出动画的真实首末关键帧，**按比例铺满这一句的起止区间** ——
出场正好落在句子结束；既不会出现「句子比动画长 → 出场演完还空一大截」，
也不会出现「动画演到一半图层就结束」。
句子短于 0.6 秒、且比动画还短时，改为**静止显示**（把动画整段挪到句子之前，整句停在最终状态），
避免一闪而过。日志会写：`预设动画跨度 2.00 秒 → 已铺满本句 5.00 秒（拉伸 2.50×）`。

**② 按真实语音时长校正每句时间**（设置 → 识别选项，默认开）：
识别完成后用自带 ffmpeg 对音频做一次静音检测（**不额外上传**），
把每句起止校正到真实说话区间，解决「说话没完字幕就没了 / 字幕还在但话已说完」。校正很保守：

| 规则 | 值 |
|---|---|
| 单侧最大调整量 | ±0.8 秒（超出就保持 ASR 原值） |
| 最短显示时长 | 0.35 秒 |
| 与相邻句 | 至少留 0.05 秒空隙，绝不重叠 |
| 找不到对应语音的句子 | 原样保留（疑似幻觉段不动） |

日志逐句回报：`第 12 句「……」8.20~9.05 秒 → 8.14~9.28 秒（+9 毫秒）`。

### 套了动画预设后字幕整句看不见？（关键帧错位）

症状：图层不透明度 100%、文字内容也在、图层名正常，**画面却一个字都没有**；
在时间线上展开该图层能看到预设的「范围选择器」，其**起始**关键帧落在句子时间之外。

原因：这类预设（打字机一类）靠**范围选择器 + 不透明度动画器**工作 —— 起始 0%→100% 时字符逐个显现。
只要「起始」停在 0%，整句就是全透明（图层自己的不透明度与它无关）。
而 AE 是把预设的关键帧写在**当前时间（播放头位置）**上的：早先版本假设「预设一定从 0 秒开始」，
播放头不在 0 时就会把动画平移过头，窗口整个落到句子之外 —— 于是整句透明。

现在的做法：套完预设后**先读真实的最早关键帧**，再按「目标时间 − 最早关键帧」平移，不再做任何假设；
面板日志会写明「预设动画原本最早在第 X 秒 → 已整体平移到第 Y 秒」。

**已经建好的图层**不用重建：字幕样式页点「**修复动画关键帧错位**」，
它会把「关键帧落在层时间范围之外」的图层整体搬回各自的时间范围

### AE 侧编译成 .jsxbin（v0.8.1 起）

分发包里 `jsx/` 只有 `ae-bridge.jsxbin`，**没有明文 .jsx**；manifest 的 ScriptPath 指向它。
开发目录 (`cep/`) 一行没动，本地调试照旧用明文。

| 层 | 能不能保护 | 说明 |
|---|---|---|
| **AE 侧 ExtendScript**（`ae-bridge.jsx`） | ✅ 编译成 `.jsxbin` | Adobe 自家的二进制/编码格式，104.8 KB → 79.1 KB |
| 面板 HTML / CSS / JS | ❌ 只能明文 | 跑在 CEF 里，必须可执行 —— 编译/加密无从谈起，如实保留 |
| pipeline（Node） | 未处理 | 同上，要保护得打包成 exe，代价是杀软误报 |

> ⚠️ **准确认识**：`.jsxbin` 是**混淆**不是加密 —— Adobe 与第三方文档都明说
> "第三方反编译器能还原出接近原始的源码，只是变量名会乱"。它挡的是随手翻代码，不是决心。
>
> 另外：**pipeline 已无任何 runtime 第三方依赖**（v0.9.0 起），
> 所以即使把它编译/打包保护起来，也**不再有 GPL 源码随附义务**。
> 当前必须随包保留的只有 ffmpeg 的 LGPL 许可全文与 Node 的 MIT 声明，
> 见 `THIRD-PARTY-NOTICES.md`。

**编译依赖**：`npm install jsxbin --prefix tools/jsxbin-tool`（26 MB，不进分发包）。
找不到编译器时打包脚本会**打警告并退回明文**，不会静默产出坏包。

**验证**：`python test/jsxbin-scriptpath-test.py` —— 装一个独立 ID 的测试扩展、自动打开面板、
检查桥接层函数是否真的注入（会启动 AE，约 1~2 分钟；不动你正在用的面板）。
改了 manifest / ScriptPath / 打包方式后应该跑一次。

**要告诉对方的一件事（最容易漏、后果最直接）**：AE 默认**不允许脚本写文件**，
必须手动开一次 —— `编辑 > 首选项 > 脚本和表达式 > 勾上「允许脚本写入文件和访问网络」`。
不勾的话第一次生成字幕会在「导出音频」那一步失败，而报错不会指向这个开关。
bat 和「安装说明.md」里都写了，见 `安装说明.md` 第二节第 3 步。

**为了分发做的几处改造**：

1. **不再有本机路径**：面板会用 CEP 的 `getSystemPath("extension")` 自动找到随包的 `pipeline/`；
   自带的 `node-runtime/node.exe` 优先于系统 Node —— 别人机器上不装任何东西也能跑
2. **数据与程序分离**：分离环境（约 7 GB）与模型默认落在「我的文档/AE自动字幕」，
   不塞进 CEP 系统目录；老位置已有环境的会自动沿用，不会让人重下 900 MB 模型
3. **砍掉 ffprobe（77 MB）**：它只用来读「时长 / 有没有音轨」，改成 ffmpeg 自己解析 ——
   两条路的结果已做**逐字段比对**（`test/probe-both-ways.mjs`），完全一致
4. **AE 侧编译成 `.jsxbin`**：只编译 ExtendScript（面板跑在 CEF 里编译不了）。
   本机实测：同一套端到端用例，明文版与 jsxbin 版的结果 **96 个字段逐字段一致**；
   又用一个独立 ID 的测试扩展自动打开面板，确认 **manifest 的 ScriptPath 确实能加载 .jsxbin**
   （5/5 个桥接层函数成功注入）—— 见 `test/jsxbin-scriptpath-test.py`

> **没砍什么**：所有功能一个不少。不带的是模型（934 MB）、Python 环境（6.9 GB）、
> 测试与设计稿 —— 这些本来就不该进分发包（前两者在你机器上按需生成）。

### 只想要人声，不想要字幕？（v0.7.2）

首页的主操作分成两颗按钮：

| 按钮 | 做什么 |
|---|---|
| **分离人声** | 导出 → 本地分离 → 落轨。**不上传云端、不识别、不建字幕层** —— 音频全程不出本机 |
| **▶ 生成字幕** | 完整流程：导出 → 分离（若开启）→ 云端识别 → 建字幕图层 |

「分离人声」跑完会问一句「要不要接着识别并生成字幕」：

- 选 **先不用** → 到此为止，人声已经能用了，也不消耗一次云端识别
- 选 **接着识别** → 直接拿刚分离出的人声当识别输入，**不会重复导出、重复分离**；
  产物名沿用同一个（人声文件与 json / srt 天然配对）

两点说明：

- 它**不看**「人声分离设置」页那个总开关（那个开关只管「生成字幕时要不要顺带分离」）——
  你既然点了这颗按钮就是要分离；前提是本机装好了分离环境（没装会明确提示去哪装）
- 落轨规则与「生成字幕」完全一致：视频素材自动关掉源层声音开关 + 人声紧贴其下方；
  音频素材会弹窗问「替换 / 放到下方」

### 清理（两个按钮 + 一个模型清理）

| 位置 | 按钮 | 做什么 |
|---|---|---|
| 首页 | **清理内存**（火箭） | 把各程序「占着不用」的内存页还给系统。**不结束任何进程**，也**跳过 AE 本身**；实测 16GB 机器一键释放约 0.4 ~ 1.9 GB |
| 首页 | **清理插件文件**（垃圾桶） | 清掉中间音频、人声分离产物、系统临时文件。（二级确认，可勾选） |
| 人声分离 | **清理模型**（垃圾桶） | 删掉已下载的模型文件，模型列表元数据保留 |

**安全设计**（清理这件事，宁可少删也不能删错）：

- **一律走回收站**，可还原；只有你在确认框里勾了「放不进回收站的项改为彻底删除」才会永久删除
- 清理范围是**白名单式的已知位置**：`<输出目录>/_中间音频`、`<输出目录>/_人声分离`、`%TEMP%` 下**我们自己命名**的临时文件（`aesub-*`、`体检帧_*`、面板日志）
- 输出目录里的字幕文件**不只看扩展名**：会读一小段内容确认「这确实是插件生成的字幕」（json 是段落数组、srt 是标准时间码结构），**不像的就不动** —— 免得删到你自己的文件
- 纯文本 `.txt` **不自动清理**（太通用，无法可靠区分）
- **Python 运行环境默认不勾**（6.9 GB，删了要重装）；**模型不在这个按钮里**（用「清理模型」单独处理）
- 被占用、删不掉的文件**跳过并如实回报**，不做任何强制手段

### 速度实测

环境：**RTX 4060 Laptop 8GB + i7-13620H + 16GB**，素材 30 秒（各跑独立进程，避免相互干扰）：

| 模型 | 人声 SDR | 设备 | 用时 | 相对素材 |
|---|---|---|---|---|
| Kim Vocal 2（MDX-Net · ONNX） | 10.2 | CPU | 18.1 秒 | 0.60× |
| Kim Vocal 2（MDX-Net · ONNX） | 10.2 | **GPU** | **4.3 秒** | **0.14×** |
| MelBand Roformer（`vocals_mel_band_roformer`） | **12.6** | **GPU** | **5.4 秒** | **0.18×** |
| MelBand Roformer | **12.6** | CPU | 未测（慢到不实用） | — |

**真正的收益不是"快了几倍"，而是"用得起最好的模型"**：

- 纯推理提速 **4.2 倍**（18.1 → 4.3 秒）
- 端到端（含模型加载、转码、识别）30 秒素材：CPU 25.7 秒 → GPU 14.1 秒；
  素材越长，固定开销被摊得越薄，越接近纯推理的 4 倍
- 而**质量最高的 MelBand Roformer（12.6 分）在 GPU 上只要 5.4 秒**，
  与最快的模型几乎持平 —— 所以有 GPU 时没有理由再用低质量模型

> 注意：CPU 基准会明显受内存影响。本机 16GB，实测**内存紧张时同一测试会从 18 秒变成 93 秒**；
> 上面 CPU 一栏取的是独立干净进程的稳定值。GPU 侧稳定得多。

> **Python 版本必须是 3.10 ~ 3.13**（面板会自动探测，优先顺序：手填路径 →
> `py -3.13/-3.12/-3.11/-3.10` → PATH 上的 python → 常见安装位置）。
> 原因：依赖里的 `diffq-fixed`、`torch` 只提供到 3.13 的预编译包；**Python 3.14 没有**，
> pip 会退回源码包编译（且该源码包本身缺文件），必然失败。
> 若 venv 已存在但版本不对，面板会删掉重建（venv 是插件自建的，删除无副作用）。

> 分离是本机运算，音频不会因为这一步离开电脑。
> **速度取决于模型，差别极大**：MDX-Net 类（如默认的 Kim Vocal 2）在 CPU 上实测约
> **0.5× 素材时长**；而 Roformer 类大模型（12.6 分那种）在 CPU 上慢到不实用，**需要 GPU**。
> 具体数字见下方「速度实测」。

### 分离出的人声会落成时间线图层（混剪用）

识别只是顺路搭车，**分离出的人声本身会变成一条可编辑的轨道**，方便混剪时单独取用。

| 源素材类型 | 自动处理方式 |
|---|---|
| **视频**（如 MP4） | 关掉源层的**声音开关**（`audioEnabled=false`），人声层紧贴它**下方** |
| **音频**（如 WAV/MP3） | 跑之前**弹框问**：`替换原音频` 还是 `放到它下方` |
| └ 替换 | 删掉原层，人声**占据它原来的图层位**（原素材仍在项目面板，可拖回） |
| └ 放到下方 | 原层保留并照旧发声，人声作为独立一条轨道 |

要点：

- **关声音开关 ≠ 删除**。BGM 还留在原来那条层上，随时把开关拨回来就能拿回原声。
- 人声文件落在 `<输出目录>/_人声分离/<合成名>_人声.wav`，**长期保留**（AE 图层引用的是文件路径，
  删了图层会变红离线）。伴奏默认删掉，勾了「保留分离后的人声文件」才留。
- 同一素材重复跑会**复用**工程里已有的素材项，不会把项目面板堆满；重名图层自动退让为 `xxx_人声 2`。
- 若选中的层本身就是上次生成的 `xxx_人声`，面板会**自动跳过分离**（对人声再分离只会得到垃圾）。
- 人声层的出入点会收拢到源层的可见范围，时间按导出区间对齐，**不需要手动对位**。

### 文字动画预设

在「字幕样式」页选一个 AE 的 `.ffx` 预设，生成字幕时会逐层套上。
下拉里会列出 **AE 自带的 300 个文字预设（18 个分类）**，以及你在
`动画 > 保存动画预设` 里另存的（归到「我的预设」）。

**搜索**：预设下拉上方有搜索框，输入即过滤（纯前端过滤，不往返 AE 所以不卡）。
关键词可匹配 **预设名**（AE 中文版是中文名，如「飞入」「打字机」）、
**分类英文名**（`Animate In`）、**分类中文别名**（入场 / 退出 / 模糊 / 缩放 / 旋转 / 路径 / 多行…）
以及完整路径。之所以要有别名表：AE 中文版的**预设名是中文**，但**分类名仍是英文**，
不补中文别名的话搜「入场」会得到 0 个 —— 而实际有 40 个入场预设。

两个实测过的要点：

- **预设不影响字幕居中**：AE 自带的文字预设都通过「文本动画器」实现（实测 12 个样本全部如此），
  动的是字符级别的偏移，不与图层的「固定居中」冲突。极少数预设若改写了图层位置，
  落点就由预设决定，面板会自动不再强制居中，并在日志里说明。
- **关键帧会自动平移**：预设的关键帧原本从 0 秒开始，而「每句一层」模式下字幕_005 可能 12 秒才出场。
  生成时会把这些关键帧整体平移到该句的出场时刻，否则动画全落在出场之前、看起来像"没生效"。

**「跑自检」按钮**（在 ⚙ 设置 → 环境与诊断 里）：安全地验证三条关键路径，**一键排查"到底是哪一环坏了"**。

| 检查项 | 怎么验 |
|---|---|
| 字体检索 | `app.fonts` 是否可用、家族数、命中数，以及**首次耗时 vs 走缓存耗时** |
| 时间范围 | 当前选中的图层能算出什么区间（起止秒数、时长） |
| **字幕居中** | 临时建「短 / 中 / 长」三个文本层，算出**文本块中心在画面里的实际落点**与中线比对，误差 ≤1px 为通过 |

居中是**用数学算出来的，不靠肉眼**——而且刻意测三种长度，因为"居中"的本质就是"与文本长度无关"。
自检**不会导入素材、不会新建合成、不改动已有图层**：临时文本层量完立即删除，
全程不改工程的"已修改"标记。完整报告写到 `%TEMP%\ae-subtitle\selftest.json`。

### 字幕位置：固定在画面正中央

字幕的落点是**写死的**（垂直 50% / 水平中线），面板不提供位置调节 —— 少一个没人调的控件。

实现上有一个容易被忽略的细节：**`addText` 生成的文本图层，锚点落在哪儿由 AE 内部决定**，
光设 `Position` 只是把那个锚点挪到目标坐标，文本块本身可能是偏的。
所以代码里会用 `sourceRectAtTime` 量出文本块包围盒、把**锚点搬到包围盒中心**，再设 `Position` 到画面中线：

```jsx
var r = layer.sourceRectAtTime(t, false);
anc.setValue([r.left + r.width / 2, r.top + r.height / 2]);   // 锚点 = 文本块中心
pos.setValue([comp.width / 2, comp.height / 2]);              // 再把中心摆到画面中线
```

同时把段落设为**居中**（`CENTER_JUSTIFY`），这样两行长短不一时每行都对齐中线，不会看着歪。

> 已知边界：「单层 + 关键帧」模式下文本会随时间变化，而锚点是建层时算一次的，
> 各行长短差异很大时可能有轻微偏移。要严格居中就用**每句一层**（默认模式）。

为什么做这个：**CEP 12 面板里中文输入法的候选浮窗会卡在屏幕左上角** —— 这是
Adobe 官方确认的缺陷（`CEP-3029`，CEP 9/10 没有这个问题），第三方扩展改不了。
既然打汉字难受，就让主要用法不需要打汉字。命中时计数那块会标出「按拼音匹配」。

- 拼音匹配优先级：字面前缀 > 首字母前缀 > 全拼前缀 > 字面包含 > 全拼包含 > 首字母包含
- 首次打拼音会向 AE 要一次**全量**字体清单（缓存在面板里），之后不再往返 AE，打字更跟手
- 全量拿不到时（AE 字体服务刚启动）自动退回按名称搜索，不会让你白打

### 字体（两种用法）

**用法一 · 搜索**：在「字幕样式 → 字体」里输入关键词（中文名、英文家族名、PostScript 名都能匹配），
下拉里每一项是「家族 · 样式」，选中即生效。空搜索框时会列出**你最近用过的字体**和常见中文字体。

**用法二 · 拾取（最省事）**：在时间线上点一下你惯用的字幕图层，点「拾取」，
字体 / 字号 / 颜色一次读过来。这也是唯一不依赖字体列表接口的办法（老版本 AE 可用）。

> 注意：字体列表需要 **AE 24.0 及以上**（用的是 `app.fonts`）。
> 面板每次搜索只在 AE 侧过滤、只回传命中的几十条，并在 AE 侧缓存了家族列表，
> 所以边打字边搜不会卡。
>
> **搜不到系统里明明装着的字体？** —— v0.5.1 起已从根上修好，正常不会再有。
> 根因是 AE 的**字体服务是异步加载**的：面板一打开就去取，那时列表可能残缺甚至为空，
> 而旧代码会把这份残缺列表**固化**（"要不要重建"的判断写了 `=== null`，空数组不算 null），
> 于是之后一直搜不到，非重启 AE 不可。现在有三层自愈：
> ① 空结果/异常**不写缓存**；② 家族数 < 20 视为不可信、下次自动重建；
> ③ 搜索 0 命中且缓存超过 1 分钟会重建再搜（覆盖"你中途装了新字体"）。
> 另外还有**「刷新列表」**按钮（在字体下拉左边）可强制重扫；下方会显示"共 N 个家族 / 匹配 M 个"便于核对。
> 面板启动时也会自动重试最多 3 次，不用手动干预。

### 识别引擎怎么选（v0.9.0 新增）

面板「设置 → 识别选项 → 引擎」里切换。**引擎清单由 `pipeline` 提供**
（`node cli.js --list-asr`），所以以后加一家新服务商只改 pipeline，面板不用动。

| 档位 | 花费 | 时间戳 | 国内直连 | 适合 |
|---|---|---|---|---|
| **硅基流动 SiliconFlow**（默认） | **免费**（SenseVoice，不收费不限量） | ❌ 只回文字 | ✅ | 日常使用、预算为零 |
| **腾讯云 录音文件识别** | 每月 **10 小时**免费额度 | ✅ 句级 + **词级** | ✅ | 要精细对齐、商用交付 |
| **Groq（Whisper）** | 免费层约 2000 次/日、8 小时/日 | ✅ 句级 | ❌ 需代理 | 英文内容、已有代理 |
| **自建 / 其他 OpenAI 兼容** | 看你自己 | 看你用的模型 | ✅ | 内网部署、数据不出门 |

**关于"免费档没有时间戳"这件事 —— 这是本插件最值得说明的一处设计：**

字幕必须有时间轴。拿不到服务商的时间戳时，流水线会：

1. 用 ffmpeg 静音检测找出所有**说话区间**；
2. 把相邻区间合并成 ≤ 24 秒的"呼吸块"（块边界落在静音里，**不会把词切断**）；
3. **逐块**送去识别 —— 每块的起止时间就是这块文字的**真实**时间范围；
4. 块内若有好几句，再按**去标点后的字数**比例分配，并把切分点吸附到块内的停顿上。

所以：**块级时间是真时间**，块内分配是**近似**。
如果说话人全程不停顿地连说一分钟，块内分配只能按字数平均 ——
这是"服务商不给时间戳"的物理上限，不是 bug。想要逐句精准，就选腾讯云/Groq。

三种情况都会自动处理：文件超过服务商上限时**照样切块**；
某一块识别失败时**如实汇报缺了几块**（不静默丢弃）；
服务商号称有时间戳却只回了文字时，**自动降级**到上述重建流程。

自测（离线、不需要密钥，用合成音频跑通整条链路）：

```bash
node pipeline/_selftest-asr.mjs     # 48 条断言
```

## 六、必须知道的约束

1. **识别时音频会上传到「你所选引擎」的云端，请勿处理机密内容。**
   这是架构决定的：本插件不做本地识别。想数据不出门，就把引擎指向自建的
   OpenAI 兼容服务（`--asr-base-url`，或面板高级里的「服务地址」）。

2. **单文件上限由服务商决定，不再是写死的 200 MiB。**

   | 档位 | 单文件上限 | 单次时长上限 |
   |---|---|---|
   | 硅基流动 | 50 MB | 1 小时 |
   | Groq | 25 MB（免费层） | 1 小时 |
   | 腾讯云（直接传数据） | 约 5 MB（base64 后 5 MB） | 5 小时 |

   流水线按时长与上限**自动选格式**：预估 WAV 装得下就无损上传，装不下就降级
   MP3(48kbps)（体积约为 WAV 的 1/5.3）；再装不下就**切块分多次提交**。
   实测 MP3(48kbps) 的识别结果与 WAV **逐字一致**。

3. **需要 Node 18 或更高版本**。CEP 面板内置的 Node 是 17.7.1，太旧，
   所以面板只负责 `spawn` 一个外部 Node 去跑流水线。分发包自带
   `node-runtime/node.exe`；也可在「环境与诊断」里手动指定 Node 路径。

4. **免费档不返回时间戳**，时间轴由"静音切块"重建（原理与精度边界见上文
   「识别引擎怎么选」）。想要逐句精准就选腾讯云或 Groq。

5. **密钥存在面板的 localStorage 里（明文）**。这是"免登录、开箱即用"的取舍。
   不想让密钥落盘，就别在面板里填，改用环境变量 `AESUB_API_KEY` /
   `AESUB_SECRET_ID` / `AESUB_SECRET_KEY`（流水线会优先读它们）。

6. 面板的「限制单次处理时长」默认 10 分钟：选中素材超过该长度时只处理开头一段，
   并在日志里说明。这是防止误选超长素材的第二道保险 ——
   也顺带避免一次烧掉大量免费额度。

## 八、技术要点（踩过的坑，改代码前务必看）

### AE 脚本

- **AE 脚本无法设置输出模块的 Format**（官方明确只读）。只能套用已有模板。
- **模板名完全不能用来推断格式**：本机名为「无损」的模板实际是 AVI。
  必须遍历全部模板逐个 `applyTemplate()` 后用 `getSetting("Format")` 读回校验。
- 本机 18 个输出模板里只有 3 个能出音频：`AIFF 48kHz`(AIFF)、`具有 Alpha 的高品质`、`高品质`(QuickTime)；
  **没有原生 WAV 模板**，所以必须用 ffmpeg 转 WAV。
- 修改输出模块设置后 **OutputModule 对象会失效**，每次读写都要重新 `outputModule(1)`。
- `renderQueue.render()` 同步阻塞，且会渲染队列里**所有** `render=true` 的项 ——
  必须先快照并关闭用户已有队列项，结束后还原。
- **`timeSpanStart` / `timeSpanDuration` 是官方文档记载的 read/write 属性**
  （设置它等价于在 Render Settings 里设自定义起止时间）。
  它们决定渲染范围，**不设就等于整段合成** —— 这是 1.98GB 事故的根因。
  社区反馈 AE 对非整帧时间点有取整怪异行为，所以：**写入后必须回读**，
  用回读值当字幕偏移量（`offsetSec`），自动纠正取整误差。
- **`layer.inPoint` / `layer.outPoint` 用的就是合成时间**（不是图层自身时基），
  所以音频内容结束点 = `max(layer.outPoint)`，**不要再叠加 `startTime`**（会翻倍）。
- **`L.timeStretch` 恒为 `undefined`**，正确属性名是 `L.stretch`（百分比，100 = 未变速）；
  `AVLayer.duration` 也不存在。

### 自动化验证：改完 AE 侧代码怎么自测（不用人工点）

`AfterFX.exe -r <脚本>` 这条通道**是完全可靠、可无人值守的**（实测：脚本跑完 AE 自行退出）。
配套两个脚本，改完 AE 侧代码直接跑，看 JSON 报告即可：

```bash
"$AE" -r "test/ae-e2e-cli.jsx"        # 端到端：范围探测 / 按范围导出 / 建图层 / 居中几何
"$AE" -r "test/ae-selftest-cli.jsx"   # 面板自检函数 AESub_selfTest 的代码路径
```

两者都在**空工程**里自建临时合成与临时素材，跑完自删，工程项数跑前跑后一致（实测 0 → 0）。
结果分别写到 `test/output/ae-e2e-result.json`、`test/output/ae-selftest-result.json`。

#### 两个必须知道的坑（都会把"脚本跑了"伪装成"脚本没跑"）

1. **ES3 保留字不能当对象字面量的键**。`{ native: x }` 会让 AE 报「非法使用保留字」，
   `$.evalFile()` 整体失败——面板和命令行一起瘫痪。
   **`node --check` 查不出来**（Node 认为合法）。写完务必扫一遍：
   ```bash
   grep -nE '(^|[{,[:space:]])(native|class|char|int|long|short|boolean|enum|const|final)[[:space:]]*:' 你的.jsx
   ```
2. **进度日志第一条必须用 `"w"` 模式**。用 `File.open("a")` 写一个**不存在**的文件会**静默失败**，
   于是脚本就算真跑了你也什么都看不到。

排查三分法：脚本第一行先落一条痕（`"w"` 模式），再 `$.evalFile` 后落一条。
连第一条都没有 → 启动/通道问题（被强杀过的 AE 偶尔要重跑一次）；有第一条没第二条 → evalFile 报错（看错误文字）。

另外两个诊断脚本：`test/ae-probe-windows.py`（列出 AE 的所有顶层窗口，看有没有 `#32770` 对话框）、
`test/ae-probe-dialog.py`（进一步读出对话框的按钮与文字）。

### 字体（AE 24.0+）

- **枚举字体**：`app.fonts.allFonts`，返回的是**二维数组**（按家族分组），
  没有 `getFonts()` 这类方法。每个 Font 对象有 `familyName` / `nativeFamilyName`（中文名）/
  `styleName` / `postScriptName` / `isSubstitute`。
- **最近使用**：`app.fonts.mruFontFamilyList`（24.6+），拿来做默认值和排序很合适。
- **必须缓存**：Font 对象的属性访问要跨 AE 内部代理，遍历上千个对象很慢。
  边打字边搜的场景下每次重扫会明显卡顿，所以要摊平成普通数组缓存起来。
- **写字体优先用 `TextDocument.fontObject`**（24.0+），拿不到再退回 `font` 字符串。
- ⚠️ **AE 找不到指定字体时不报错，而是静默替换成替代字体。**
  所以写完**必须回读** `td.font` 与期望值比对，不一致要如实告诉用户。
- ⚠️ `TextDocument.fontFamily` / `fontStyle` 是**只读**的，只能读不能写。
- ⚠️ `Font` 对象是"软引用"：字体代理被移除后访问属性会**抛异常**，
  替代字体（`isSubstitute`）的引用更不保证可读 —— 所有属性读取都要包 try/catch。
- **拾取路径**（从选中的文本图层读样式）不依赖字体列表接口，是最稳的兜底方案。

### 流水线

- 我们**只把"自己转好的标准音频"交给识别服务**（16kHz 单声道），
  不把原始媒体直接丢过去 —— 各家的格式差异与内部实现都被这一步抹平了。
- ⚠️ **别让外部库自己去 spawn ffmpeg**：那类实现依赖 PATH，
  找不到时会抛出**误导性的**「no audio track」。流水线一律用绝对路径自己调。
- **`aifc` 模块在 Python 3.13 已被移除**，解析 AIFF 头要手写。
- ffmpeg 走 `pipeline/vendor/ffmpeg/`（**LGPL 构建**，随包）。
  开发机上也可以用 npm 的 `@ffmpeg-installer/ffmpeg` 兜底 ——
  但注意那个包**声明是 LGPL、实际二进制是 GPL**，别把它的二进制打进分发包。
- 转码后的中间文件默认删除，`--keep-wav` 保留；切块临时文件默认删除，`--keep-chunks` 保留。
- **腾讯云签名是手写的 TC3-HMAC-SHA256**（零依赖）。
  改动签名相关代码后**务必**跑 `pipeline/_selftest-asr.mjs`：
  里面有"签的头必须与发的头逐字符一致"这类断言 —— 这类错在线上只表现为一个 403，极难查。
- 拿不到时间戳的档位靠 `lib/align.js` 重建时间轴；
  改那里要特别小心**区间边界是双关的**（既是上段尾部又是下段头部），
  自测里有一条专门盯这个 bug 的断言。
